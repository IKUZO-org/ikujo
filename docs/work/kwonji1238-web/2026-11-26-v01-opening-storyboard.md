## 프롬프트 요약
앞의 요청(#38 PR 올리기, develop 직접 push 문의)은 #38 작업 기록에 있다. 이 브랜치는 그 뒤 요청부터다.
1. #38 PR이 올라간 뒤 develop 직접 push를 요청했다가, PR로 올리려면 브랜치를 origin에 올려야 하고 main에만 push하지 않으면 된다는 뜻이었다고 정정 (develop 직접 push는 하지 않음)
2. 이제 본격적으로 작업을 시작하자고 함 → 다음 작업을 V-01 오프닝 콘티로 보고 이슈 초안을 보여 줌
3. 장면마다 브랜치를 새로 만드는지 질문 → 이슈 하나에 브랜치 하나라고 설명
4. 같은 브랜치에서 계속 작업하고 이슈와 PR만 올리면 되는지 질문 → 머지 뒤 브랜치 삭제와 PR당 브랜치 하나 때문에 안 맞는다고 설명
5. 제안대로 V-01부터 진행하자고 함 → 이슈 #43을 만들고 콘티 작성
6. 스토리보드를 이렇게 만들지 말고 공통 스타일, 컷 표, 스토리보드(컷 번호가 붙은 이미지, 참고 이미지 첨부) 세 가지만 만들어 달라고 함. 소리는 따로 만들지 말고 영상 프롬프트 안에 넣으라고 함 → 문서를 세 부분으로 다시 쓰고 소리를 프롬프트로 옮김

- 영상 생성은 M4. 생성 직전에 예상 크레딧을 알리고 지영 승인을 받는다. 영상 파일 위치(VQ-3)를 정하기 전에는 편집본 v2 한 개 말고는 영상 파일을 커밋하지 않는다
- 다음 영상은 P2(V-06, V-07 엔딩)이고, 영상마다(또는 쌍마다) 새 이슈와 새 브랜치로 시작한다
- `scripts/usage/lib.mjs` 의 `inside()` 가 Windows의 역슬래시 경로를 못 맞춰 사용량이 0으로 나온다 (#38 기록 세션 2 참고). 이 기록을 쓰는 시점에 이슈는 만들지 않았고 별도 세션 카드로 제안만 했다. 아래 사용량 0은 이 버그 때문이다
