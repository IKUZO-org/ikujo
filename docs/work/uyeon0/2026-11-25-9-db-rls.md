## 할 일
data §2~3, §7대로 표, RLS, `tally`를 마이그레이션으로 만들고, 남의 비밀이 0줄인지 로컬 Supabase에서 테스트한다. `join_room`은 단계 4로 넘긴다.

## 한 일
- `supabase/config.jsonc`: `supabase init`(CLI 3.4.0)으로 만듦. `project_id`를 `ikujo`로, 로컬 익명 로그인(`enable_anonymous_sign_ins`)을 켬. Postgres 17은 원격과 같음
- `001_core.sql`: 표 13개와 인덱스
  - data §2의 제약: `rooms.code` 숫자 6자리 + 진행 중 방끼리 unique, `players` unique 2개, 출몰 판당 1번 unique (AC-053)
  - 범인, 희생자는 `game_secrets`에만 둠
- `002_rls.sql`: 모든 표 RLS, 읽기 정책만 둠 (쓰기는 서버가 service role로)
  - 도우미 함수 `my_player`, `is_room_member`, `is_game_member`, `is_me` (security definer, `search_path` 비움)
  - `assignments`, `votes`: 본인 것만 / `game_secrets`, `events`: 정책 없음 / `reveals`: 참가자 + `reveal`, `ended` 단계 / 속삭임은 당사자, 출몰은 참가자
  - 익명 손님도 `authenticated` 역할이라 "로그인했으면 읽기" 정책은 쓰지 않음
  - `anon`, `authenticated`의 쓰기 권한(insert, update, delete, truncate 등)을 회수함. RLS와 두 겹으로 막고, RLS가 적용되지 않는 truncate도 막음. 뒤에 만드는 표에도 같은 기본값을 적용
  - `players`는 열 단위 권한으로 `id`, `room_id`, `nickname`, `seat`, `left_at`만 읽게 함 (data §3 "닉네임, seat, left_at"). `user_id`, `is_guest`, `joined_at`은 서버만. 클라이언트는 `select("*")` 대신 칸 이름을 적어서 읽어야 함
- `003_functions.sql`: `tally(game_id, round)`가 최다 득표자 목록을 돌려줌. 해설 전 집계는 비밀이라 `service_role`만 실행 가능
- `tests/db/`: 로컬 Supabase에 익명 손님 세션을 만들어 RLS 8개, `tally` 5개를 확인. 꼭 필요한 것만 남김. `npm run test:db`로 따로 돌리고 `npm test`에서는 뺌
- vitest 설정을 `.mts`로 바꿈 (실행할 때마다 나오던 ESM 경고)
- `postcss.config.mjs`: 단계 1에서 남은 lint 경고(`import/no-anonymous-default-export`) 고침
