### 1.1 단계 (phase)
판의 단계는 서버가 `games.phase`에 하나만 둔다. 폰은 이 값과 `phase_ends_at`을 보고 그린다.

```
lobby → intro → secret → r1 → r2 → r3 → vote → (revote) → reveal → ended
```

| 단계 | 들어가는 조건 | 나가는 조건 | 길이 |
| --- | --- | --- | --- |
| lobby | 방 만들기 | 방장이 시작 (4~6명) | — |
| intro | 시작 + 배정 완료 | 시간 끝 또는 모두 "다음" | 3분 `제안` |
| secret | intro 끝 | 모두 확인 또는 시간 끝 | 2분 `제안` |
| r1 | secret 끝 | 시간 끝 (모두 준비 시 먼저: `미정` OQ-007) | 8분 |
| r2 | r1 끝. 희생자가 유령이 된다 | 시간 끝 | 10분 |
| r3 | r2 끝 | 시간 끝 | 8분 |
| vote | r3 끝 | 모두 투표 또는 시간 끝 | 3분 |
| revote | vote가 동점 | 모두 투표 또는 시간 끝 | 1분 `제안` |
| reveal | 투표 판정 | 방장이 다시 하기(→ 새 판) 또는 홈으로(→ ended, `endRoom`) `확정` | — |
| ended | 방장이 reveal에서 홈으로, 범인 이탈(`제안`, OQ-006). D-019의 30일 삭제는 이때부터 센다 | — | — |

- 단계 넘기기는 서버 함수 `advance(gameId, from)` 하나로만 한다. `from`이 지금 단계와 다르면 아무것도 안 한다(여러 폰이 동시에 눌러도 한 번만 넘어감)
- 시간이 끝나면 아무 폰이나 `advance`를 부른다(타이머가 0이 된 폰). 서버는 `phase_ends_at`이 지났는지 확인한다

## 3. 화면별 명세

### S-02 홈
| 요소 | 동작 |
| --- | --- |
| 방 만들기 | 닉네임이 없으면 S-03(닉네임) → 방 생성 → S-05 |
| 코드 입력 (숫자 6자리 `제안`) | 입장 요청 → 성공 S-05 / 실패 한 줄 안내 |

입장 오류 (AC-011)
| 경우 | 안내 |
| --- | --- |
| 없는 코드 | 없는 방이에요 |
| 6명 참 | 방이 꽉 찼어요 (6명) |
| 이미 시작 | 이미 시작한 방이에요 |
| 내가 이미 들어간 방 | 오류 없이 그 방으로 (다시 들어오기) |

### S-03 닉네임 (FR-003)
- 1~10자, 앞뒤 공백 제거. 같은 방에 같은 이름이 있으면 서버가 "이름2"로 바꿔 준다 `제안`
- 처음 들어올 때 익명 세션을 만들고, 이 폰에 세션이 남는다. 같은 폰으로 다시 열면 같은 자리 (NFR-002)

### S-05 대기실 (FR-012, FR-013)
| 요소 | 동작 |
| --- | --- |
| 방 코드 (크게) | 눌러서 복사 |
| 참가자 목록 n/6 | 실시간. 방장 표시 |
| 시작 (방장만) | 4명 미만이면 꺼짐 + "4명부터 시작해요" (AC-012). 누르면 `startGame` |
| 나가기 | 플레이어 삭제. 방장이 나가면 다음 사람이 방장 (BR-012) |

### S-06 배정 중 (FR-020)
- "진행자가 사건을 준비하고 있어요". 15초 넘으면 "조금만 더 기다려 주세요" 후 서버가 규칙 배정으로 바꾼다 (NFR-003)

### S-07 오프닝 (FR-021)
- 공용: 방송 예고 → 가상 단톡방 PD 메시지 → 정전 → 발견 내레이션 (§11). 글 + TTS(`미정` OQ-011) + 소리
- "다음"은 각자. 모두 누르거나 3분이 지나면 S-08

### S-08 인물 카드 (FR-030)
| 공용 | 개인 |
| --- | --- |
| "각자 폰으로 비밀을 확인하세요", 확인 n/N | "당신은 ○○입니다", 인물 소개, 비밀(1개), 정전 때 알리바이, 범인이면 "당신이 범인입니다. 생방송 전까지 들키지 마세요." |

- "확인했어요"를 누르면 `ready(secret)`. 모두 누르거나 2분 → r1
- AC-030: 공용 화면, 네트워크 응답 어디에도 범인 이름이 없다(범인 본인 폰의 개인 응답 제외)

### S-09 라운드 (FR-040~044)
| 공용 탭 | 내 것 탭 |
| --- | --- |
| 라운드 n/3, 장소와 시점, 이번 공용 단서, 지금까지 공용 단서 목록, 타이머, 준비 완료 n/N, 이벤트 알림 | 나에게만 온 단서 (이번 + 지난 라운드) |

- 준비 완료 버튼: 누르면 현황에 반영. 모두 준비 시 먼저 넘어가기는 `미정` (OQ-007). 1차 개발은 **타이머로만** 넘어간다 `제안`
- 이벤트(FR-044)는 S-14로 덮어 보여 주고 닫으면 라운드로

### S-10 유령 모드 (FR-050~053)
- r2 시작 때 희생자 폰: 녹화 화면이 끊기는 연출 → 유령 모드. 나머지 폰: 속보 "○○, 해변에서 쓰러진 채 발견" (AC-050, 2초 안)
| 요소 | 동작 |
| --- | --- |
| 범인 특징 | 이번 판 범인의 특징 1개 (§28.6). 그 판 인물 2명 이상에게 해당 (AC-051) |
| 속삭임 | 살아 있는 한 명 고르기 + 글(1~80자 `제안`). 횟수 `미정` (OQ-005), 1차 개발은 라운드당 1번 `제안` |
| 출몰 | 판 전체 1번 (AC-053). 모든 폰에 "생방송 연결" 덮는 화면 + 유령의 말(1~80자) |
- 유령은 투표 화면에서 고를 수도, 고를 대상이 될 수도 없다 (AC-053)

### S-11 투표, 재투표 (FR-060, BR-013)
| 공용 | 개인 |
| --- | --- |
| 생방송 문자 투표 연출, 완료 n/N, 남은 시간 | 살아 있는 플레이어 목록(나 포함 `제안`)에서 하나. 보내면 바꿀 수 없음 `제안` |

- 공용에는 완료 인원만 (AC-060). 개별 선택은 해설 전까지 서버에만
- 판정 (`tally`):
  1. 최다 득표 1명 → 판정
  2. 최다 득표가 동점 → revote. 후보는 동점자만 (AC-060-2), 1분
  3. revote도 동점 → "방송 중단"(범인 승리) `제안` (OQ-008)
  4. 아무도 안 찍음 → "방송 중단" `제안`
- 시간이 끝나면 안 찍은 사람은 기권 (BR-007). 나간 사람(BR-011)은 완료 인원 분모에서 빠진다

### S-12 해설 (FR-061, FR-070, FR-071)
순서대로 카드 넘기기:
1. 엔딩: 검거 성공 / 방송 중단 (FR-061)
2. 범인 공개, 동기
3. 투표 결과: 누가 누구를 지목했는지 (재투표 있으면 둘 다)
4. 진실 타임라인 (§28.2), 범인의 결정적 실수
5. 유령이 본 장면의 의미
6. 레드 헤링 전부 (BR-010)
7. 과거 사고(3주 차)의 진실
8. **우리 판 맞춤 해설** (D-014): 이번 판에서 누가 무엇을 숨겼고 왜 의심받았는지
9. 정확히 추리한 사람 = 범인을 지목한 사람 (D-015, AC-071). 없으면 "이번엔 범인이 이겼어요"
10. 다시 하기(같은 사람들, 새 배정) / 홈으로 `확정`
   - **방장**: 다시 하기는 `replay`, 홈으로는 `endRoom`(방이 ended가 된다). 다른 사람 화면에는 "방송이 끝났어요"와 홈으로 버튼이 뜬다
   - **참가자**: 다시 하기 버튼은 없고 "방장이 다시 하기를 고르면 새 판이 시작돼요"를 보여 준다. 홈으로는 나만 나간다(`leaveRoom`, 판과 다른 사람에게 영향 없음)
   - "끝내기"라는 버튼은 따로 두지 않는다

- 1~7, 9는 시나리오 해설 틀로 서버가 만든다(LLM 없이도 나옴). 8만 LLM(CAG) `제안` — LLM이 실패하면 8을 빼고 보여 준다

### S-13 설정 (FR-091)
소리 켜기/끄기, 진동, 온보딩 다시 보기

### S-14 가상 폰 연출 (FR-080, BR-008)
| 종류 | 모양 |
| --- | --- |
| 가상 단톡방 | 게임 속 메신저 (실제 앱 모양을 따라 하지 않음) |
| 긴급 속보 | 방송 자막 띠 |
| 전화 수신 | 가상 전화 화면, 받으면 TTS 또는 글 |
| 사진첩, 음성 메모, 잠긴 폰 | R2의 PD 폰 |
- 진짜 전화, 문자는 보내지 않는다

## 4. 서버 동작 (Server Actions / RPC)
모든 동작은 익명 세션이 있어야 한다. 실패는 `{ error: '한 줄 안내' }`로 돌려준다.

| 동작 | 누가 | 하는 일 | 검사 |
| --- | --- | --- | --- |
| `createRoom(nickname?)` | 누구나 | 방 + 코드 + 나를 방장 플레이어로 | 진행 중 방 코드와 겹치지 않게 다시 뽑기 |
| `joinRoom(code, nickname?)` | 누구나 | 플레이어 추가 | 없음/꽉 참/시작함 (AC-011) |
| `leaveRoom(roomId)` | 참가자 | lobby: 삭제. 게임 중: `left_at` 기록 (BR-011) | 방장이면 넘김 (BR-012). 범인이면 OQ-006 |
| `startGame(roomId)` | 방장 | 판 만들기 → 배정(§5) → phase=intro | 4~6명 (AC-012) |
| `advance(gameId, from)` | 참가자 | 다음 단계로. r2 진입 때 희생자 유령 처리 | `from`이 지금 단계, 시간 지남 또는 넘김 조건 충족 |
| `ready(gameId, phase)` | 참가자 | 준비/확인 표시 | 같은 단계 한 번 |
| `whisper(gameId, toPlayerId, body)` | 유령 | 속삭임 | 유령 본인, 횟수(OQ-005), 대상 생존 |
| `haunt(gameId, body)` | 유령 | 출몰 | 판에 1번 (AC-053) |
| `vote(gameId, targetPlayerId)` | 살아 있는 플레이어 | 투표 | vote/revote 단계, 한 번, 대상이 후보 |
| `replay(roomId)` | 방장 | 같은 사람들(누른 순간 접속한 사람)로 새 판 | reveal 이후, 접속한 사람 4명 이상 (PRD D-023) |
| `endRoom(roomId)` | 방장 | 방을 끝냄: phase=ended, 다른 폰에 "방송이 끝났어요" | reveal 이후 `확정` (4판) |

### 받는 것 (읽기)
| 읽기 | 누가 | 내용 |
| --- | --- | --- |
| `getRoomState(roomId)` | 참가자 | 방, 참가자 목록, 판 단계, 남은 시간, 공용 단서, 준비/투표 **인원 수** |
| `getMine(gameId)` | 참가자 | 내 인물, 비밀, 알리바이, 내 단서, (유령이면) 특징, 받은 속삭임 |
| `getReveal(gameId)` | 참가자 | reveal 단계 이후에만. 해설 전체 |

- 실시간: 방 채널 `room:{roomId}`에 `phase`, `ready_count`, `vote_count`, `haunt`, `event` 신호만 보낸다. 받으면 `getRoomState`/`getMine`를 다시 부른다 (비밀은 신호로 보내지 않음)

## 5. AI 배정 (FR-020, CAG, D-011)
1. 서버가 인원 n(4~6)으로 등장인물을 정한다: 핵심 4 + (n≥5 인플) + (n=6 의료) (BR-002)
2. LLM 호출: 고정 맥락 = 시나리오 파일 전체(캐시) + 규칙 요약. 가변 입력 = 인원, 등장인물 ID 목록, 지난 판 범인(같은 무리 연속이면 피하기 `제안`)
3. LLM은 JSON만 돌려준다: `{ culprit, victim, seats: [{playerSeat, character}], clues: {r1: {...}, r2: {...}, r3: {...}} }` — 모두 시나리오 안의 ID
4. 서버 규칙 검사 (BR-014, AC-020-*):
   - 범인은 핵심 4명 중, 희생자는 범인이 아닌 핵심 인물 (BR-003, BR-004)
   - 모든 ID가 시나리오에 있다 (AC-020-4)
   - 이번 범인의 특징이 그 판 인물 2명 이상에게 해당 (BR-006). 안 되면 그 범인은 이 인원에서 고르지 않는다 (OQ-013이 풀리기 전까지)
   - 단서 배분: 개인 단서는 그 라운드에 정해진 수만큼, 레드 헤링 포함
5. 실패하면 한 번 더. 2번 실패 또는 15초 초과 → 규칙 배정(같은 규칙으로 무작위) (NFR-003)
6. 자리 배정(누가 어느 인물)은 무작위. 결과를 `assignments`에 저장, `games.assignment_source`에 ai/rule

맞춤 해설(S-12의 8)도 같은 고정 맥락 + 이번 판 배정과 투표를 넣어 글을 받는다. 출력은 400자 이내, 시나리오에 없는 사실 금지 `제안`.

## 6. 이탈과 다시 들어오기 (BR-011, BR-012, NFR-002)
| 상황 | 처리 |
| --- | --- |
| 폰 잠김, 새로 고침 | 같은 세션이면 `getRoomState` + `getMine`으로 그 단계 화면 그대로 (AC-NFR-002) |
| 범인이 아닌 사람이 "나가기" | `left_at` 기록. 단계는 계속, 투표 분모에서 빠짐 (AC-BR-011). 다시 들어오면 `left_at` 지우고 이어서 |
| 방장 이탈 | 입장 순서상 다음 사람이 방장 (BR-012) |
| 범인 이탈 | `미정` (OQ-006). 1차 개발은 판 종료 → 해설 `제안` |
| 연결만 끊김 (나가기 안 누름) | 이탈로 보지 않는다. 투표 시간이 끝나면 기권 |
