## 할 일
규칙 문서에서 lint로 잡을 수 있는 것을 ESLint 규칙으로 넣고, Prettier와 커밋 전 검사(husky, lint-staged)를 둔다. PR 검사에 넣는 일은 PO가 한다.

## 한 일
- `eslint.config.mjs`에 규칙 4개
  - `src/server/` 밖에서 `process.env.SUPABASE_SERVICE_ROLE_KEY` 읽기 금지 (`no-restricted-syntax`)
  - `@supabase/supabase-js`의 `createClient` import는 `src/server/db.ts`와 `tests/db/`에서만 (`no-restricted-imports`)
  - `dangerouslySetInnerHTML` 금지 (`react/no-danger`)
  - `className`의 문자열, 템플릿 리터럴에 `sm:`, `md:`, `lg:`, `xl:`, `2xl:` 금지 (`no-restricted-syntax`)
- Prettier: 한 줄 100자, 나머지는 기본값(큰따옴표, 세미콜론). `format`, `format:check` 스크립트. `eslint-config-prettier`로 ESLint의 포맷 규칙을 끔
  - 포맷 대상에서 뺀 것: `docs/`와 모든 `.md`(팀 문서 사본, 작업 기록), `supabase/`(CLI 설정, SQL), `.github/`(PO 담당), 생성물
- husky + lint-staged: pre-commit에서 커밋에 들어가는 파일만 `prettier --write`, `eslint --fix`. typecheck와 test는 넣지 않음. `npm install` 때 `prepare` 스크립트로 hook 설치
- 기존 코드를 한 번 포맷함 (포맷만 바뀌는 커밋으로 분리). 파일 4개, 대부분 테스트 데이터 줄바꿈
- 새 패키지: `prettier`, `eslint-config-prettier`, `husky`, `lint-staged` (이슈 #15)

## 프롬프트 요약
1. 이슈 #15를 만들기 전에 Prettier 설정을 정함. 큰따옴표와 세미콜론은 지금 코드대로 두기로 함
2. PR 검사(CI)와 husky를 비교하고 둘 다 하기로 함. 이후 PR 검사는 CONTRIBUTING.md 수정과 같이 PO가 넣기로 하고 이슈 범위에서 뺌
