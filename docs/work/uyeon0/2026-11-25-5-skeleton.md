## 할 일
배포할 수 있는 빈 Next.js 앱을 만들고 Supabase를 붙인다. 손님도 익명 세션을 갖게 하고 typecheck, lint, test 스크립트를 둔다. Vercel 연결은 다른 팀원이 따로 한다.

## 한 일
- Next.js 16.4.6 (App Router, TypeScript, `src/`) 뼈대. `create-next-app` 결과에서 설정 파일만 가져오고 화면은 빈 첫 화면(`LAST ONE` 제목)으로 바꿈
- `src/app/layout.tsx`, `src/app/globals.css`: `lang="ko"`, 가운데 최대 430px 틀. 토큰 값은 상경 확정 전이라 넣지 않음
- `src/lib/supabase/env.ts`: 브라우저에 가도 되는 URL, anon 키만 읽음
- `src/lib/supabase/client.ts`: 브라우저용 클라이언트
- `src/lib/supabase/server.ts`: 서버에서 세션을 읽는 클라이언트 (`server-only`)
- `src/server/db.ts`: service role 클라이언트 (`server-only`, 이 파일에서만 만듦)
- `src/lib/supabase/ensure-session.ts`: 세션이 없으면 `signInAnonymously`로 만드는 `ensureSession`
- `src/proxy.ts`: 모든 화면 요청 앞에서 `ensureSession`을 부르고 세션 쿠키를 갱신. Next.js 16에서 middleware 이름이 proxy로 바뀜
- `tests/ensure-session.test.ts`, `vitest.config.ts`: 세션 있음, 없음, 익명 로그인 실패 3가지
- `package.json` 스크립트: `typecheck`(`next typegen && tsc --noEmit`), `lint`(`eslint`, Next.js 기본 설정), `test`(`vitest run`)
- `.env.example`: 이름만 3개
- `AGENTS.md`: `next dev`가 자동으로 만드는 Next.js 16 안내. 커밋하지 않으면 매번 다시 생겨서 같이 넣음
- Tailwind v4 (`tailwindcss`, `@tailwindcss/postcss`, `postcss.config.mjs`): DESIGN.md가 `md:`, `text-red-500` 같은 Tailwind 문법을 예로 들고 팀도 Tailwind를 전제로 생각하고 있어서 추가함. `globals.css`의 `@theme`에 토큰 이름만 주석으로 두고 값은 비움. 430px 틀은 Tailwind 클래스로 바꿈
- 새 패키지: `@supabase/ssr`, `@supabase/supabase-js`, `server-only`, `vitest`(dev-prompt 1단계 지시), `tailwindcss`, `@tailwindcss/postcss`(위 이유). `@types/node`는 vitest와 맞추려고 `^22`(로컬 Node 22)로 둠
- 넣지 않은 것: Vercel 설정 (다른 팀원)
- Supabase 대시보드: 익명 로그인(Allow anonymous sign-ins)이 켜져 있는 것을 확인함

7. `AGENTS.md`를 커밋하고, 커밋을 작업 단위로 나누기로 함

## 확인
- `npm run typecheck` → 통과
- `npm run lint` → 통과 (경고 0)
- `npm test` → 1개 파일, 3개 테스트 통과
- `npm run build` → 성공 (`/` 정적, Proxy 포함)
- `.next/static`에서 `SUPABASE_SERVICE_ROLE_KEY`, `service_role` 문자열 검색 → 없음
- `npm run dev` + 쿠키를 저장하는 요청 2번 → 두 번 다 HTTP 200, 같은 익명 사용자 id, 두 번째는 새 세션 쿠키 없음 (NFR-002)
- 브라우저에서 첫 화면이 열리는 것 확인
- Tailwind 추가 뒤 typecheck, lint, test(3개), build 다시 돌림 → 모두 통과. 빌드된 CSS에 `max-w-[430px]` 규칙이 들어간 것 확인. 클라이언트 번들에 service role 문자열 없음
- Vercel 미리보기 → 안 돌림 (Vercel 연결은 다른 팀원 담당)

## 남은 일
- 익명 사용자도 Supabase에서 `authenticated` 역할을 받음. 단계 2 RLS는 "로그인했으면 읽기"가 아니라 "본인 것만"으로 써야 함
- 지금은 모든 화면 요청에서 익명 사용자를 만들어서 봇, 링크 미리보기, 시크릿 창마다 사용자가 쌓임. 세션 만드는 시점을 방 입장(단계 4 Server Action)으로 늦출지 단계 4 담당과 정하기 (spec §3 "처음 들어올 때"와 같이 봐야 함)
- 익명 사용자 정리 작업: data §6 "판이 끝나고 7일 뒤 삭제"가 `제안` 상태
- 대시보드가 익명 로그인에 captcha를 권장함. MVP에 넣을지 정하기
- 확인하면서 Supabase에 테스트용 익명 사용자 2명이 생김. 지워도 됨
- `next.config.ts`의 Next 16 기본값 `cacheComponents`, `reactCompiler`는 그대로 둠. 단계 진행 화면을 만들 때 영향이 있으면 다시 봄
- ARCHITECTURE.md §3 폴더 구조의 `제안` 표시를 1단계에서 확정하고 지우기로 되어 있음. 담당자(정연, 현경)가 정할 일이라 이 PR에서는 고치지 않음
- 포맷터, 추가 lint 규칙, CI에서 lint 실행은 필요하면 별도 `[세팅]` 이슈로
