# 개발 로드맵 — 「LAST ONE」

| 항목 | 내용 |
| --- | --- |
| 근거 | PRD §22 수용 기준, §23 출시 조건, §24 위험, §25 미결정, §28.10 맡은 사람 / 개발 프롬프트 1~12단계와 부록 / 레포 규칙(develop, main) |
| 날짜 | 이 문서에는 날짜를 넣지 않는다. **순서와 묶음만** 정하고, 날짜는 조 회의에서 정해 각 마일스톤 칸에 적는다 |

## 0. 한눈에
```
M0 준비 ─▶ M1 뼈대 ─▶ M2 방에 모이기 ─▶ M3 같이 넘어가기 ─▶ M4 한 판 끝까지 ─▶ M5 버티기 ─▶ M6 출시
(결정)     1·2 ∥ 3      4·5               6·7                 8·9 (첫 시연)       10·11        12 → main
```
- 모든 작업 PR은 `develop` 으로. **`main` 은 M6에서 한 번만** (PO가 출시 PR `develop` → `main`)
- 각 마일스톤 끝에 `develop` 미리보기 주소로 조원이 직접 눌러 본다 (390×844, 실제 폰)

## 5. 출시 (`main`) 규칙
- 출시 PR은 M6 체크리스트를 조 회의에서 같이 본 뒤 PO가 만든다 (`develop` → `main`, Merge commit)
- 출시 뒤 고칠 것도 `develop` 으로 먼저. 급한 것만 PO가 다시 출시 PR
- MVP 밖(PRD §27: 온라인, QR, 대화 듣기, 시나리오 추가)은 출시 뒤 다음 로드맵에서

## 6. 갈아탈 신호
- 한 마일스톤이 두 번 연속 늦으면: 담당을 나누거나 범위를 줄일 곳(연출 자산, 설정 화면)을 회의에서 고른다
- 첫 시연(M4)에서 "재미없다"가 나오면: M5로 가지 않고 시나리오와 라운드 시간(OQ-007)부터 다시 본다
