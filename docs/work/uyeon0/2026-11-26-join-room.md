## 할 일
시작과 입장이 겹쳐도 배정 없는 참가자가 남지 않게 한다. 입장 규칙은 그대로 두고 DB 함수 `join_room` 으로 옮긴다.

## 한 일
- `supabase/migrations/004_join_room.sql`: `join_room(code, user_id, is_guest, nickname)`. 방 줄 `for update` 잠금 → 이미 참가자(나갔다 오면 `left_at` 지움) → lobby 확인 → 6명 확인 → 빈 seat, 닉네임 숫자 붙이기, 넣기. nickname 이 null 이면 확인만. 실행 권한은 service_role 만 (`tally` 와 같게). 오류 문구는 부르는 쪽(MSG)이 정함
- `core.ts` `joinRoom`: zod 검사 뒤 `store.joinRoom` 결과를 S-02 문구로 바꿈. seat 겹침 재시도 루프 제거. broadcast, `room_joined` 기록은 그대로. 닉네임 형식 오류는 전처럼 방 확인(없는 방, 시작, 꽉 참) 뒤에 알림
- `core.ts` `startGame`: `lobby → playing` 으로 바꾼 뒤 참가자를 다시 읽어 인원 확인과 배정에 씀. 모자라거나 넘치면 lobby 로 되돌리고 기존 오류. 배정 흐름은 그대로
- `store.ts`, `supabase-store.ts`: `joinRoom` (rpc `join_room`) 추가
- 테스트: 가짜 저장소에 같은 규칙의 `joinRoom`. 재시도 루프를 보던 단위 테스트 2개는 동작이 없어져 지움. `tests/db/join-room.test.ts` 추가 (동시 입장, 시작+입장 경쟁, anon 호출 막힘)
- PR 전 점검: test-pruner, comment-reviewer 로 테스트와 주석을 봄. 지울 테스트 없음
- `004_join_room.sql` 머리 주석에서 작업 내력 한 줄을 지워 첫 커밋에 합침
