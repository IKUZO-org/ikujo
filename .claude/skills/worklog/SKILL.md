# 작업 기록 쓰기

## 1. 어디에
- 아이디: `git config ikujo.login` (비어 있으면 사용자에게 묻고 저장). 소문자로 쓴다
- 브랜치: `git branch --show-current`. `main` 이나 `develop` 이면 멈추고 브랜치부터 만든다 ([CLAUDE.md](../../../CLAUDE.md) 3번)
- 파일: `docs/work/<아이디>/<YYYY-MM-DD>-<브랜치에서 '/종류-' 뒤의 주제>.md`
- 이 브랜치의 기록 파일이 이미 있으면 새로 만들지 않고, 맨 아래에 `## 세션 N (YYYY-MM-DD)` 를 붙여 같은 칸들을 이어 쓴다

## 2. 무엇을
[docs/work/_template.md](../../../docs/work/_template.md) 형식 그대로. 필수 칸 이름을 바꾸지 않는다 (PR 검사가 이 제목을 찾는다):
`## 할 일`, `## 한 일`, `## 프롬프트 요약`, `## 사용한 skill`, `## 확인`, `## 남은 일`, `## 사용량`

- **프롬프트 요약**: 이 세션에서 사용자가 준 요청을 순서대로, 요청 하나에 한 줄. 무엇을 원했고 어떤 조건을 걸었는지가 남게. 원문을 길게 붙이지 않는다
- **사용한 skill**: 이 세션에서 실제로 부른 skill, 서브에이전트, MCP 도구 이름과 용도. 없으면 "없음"
- **확인**: 실제로 돌린 명령과 결과(통과, 실패 수). 안 돌린 것은 "안 돌림"
- **한 일**: `git diff --stat develop...HEAD` 와 작업 내용을 보고 쓴다. 지어내지 않는다
- **사용량**: 맨 마지막에 `node scripts/usage.mjs --md` 를 돌려 나온 글을 그대로 `## 사용량` 칸으로 붙인다. 이미 있으면 그 칸 전체(다음 `## ` 전까지)를 새 결과로 바꾼다. 세션이 여러 번이어도 칸은 하나(브랜치 전체 합계). 숫자를 고치거나 지어내지 않는다. 결과가 0이면 그대로 두고 사용자에게 "이 레포 폴더에서 연 Claude Code 기록만 센다"고 알린다

## 3. 가릴 것 (반드시)
쓰기 전에 기록 전체를 다시 읽고 아래를 `[가림]` 으로 바꾼다:
- API 키, 토큰, 비밀번호, 접속 문자열, `.env` 의 값
- 전화번호, 이메일, 주소, 실명 외 신상, 다른 사람의 사적인 말
- 사용자가 채팅에 키를 붙였던 일이 있으면 기록에는 "[가림] 키가 채팅에 나와 폐기를 안내함" 만 쓴다

## 4. 끝
- 파일을 커밋에 넣는다 (`git add docs/work/<아이디>/...`)
- 사용자에게 기록 경로와 한 줄 요약을 말한다
