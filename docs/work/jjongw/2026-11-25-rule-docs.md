## 할 일
모두가 따를 규칙 문서를 만들고, 각자의 Claude가 일의 종류에 맞는 문서를 먼저 읽게 한다. 규칙 문서는 담당자가 직접 고치고 PO가 PR에서 검토한다.

## 한 일
- `CONTRIBUTING.md`: `docs/rules.md` 를 옮김(깃허브가 이슈, PR 화면에 링크). 맨 앞에 "어떤 문서를 따르나, 누가 고치나" 표(담당: CONTRIBUTING 신, SECURITY 정연, ARCHITECTURE 정연·현경, DESIGN 상경)
- `SECURITY.md`: 키와 환경 변수 표, 게임 비밀 정보 표(누가 볼 수 있나), 코드 규칙, 키가 샜을 때, 취약점 비공개 신고, PR 보안 체크
- `ARCHITECTURE.md`: 한 장 그림, 원칙 5개(phase 단일 진실, 쓰기는 서버, 비밀은 본인 요청에만, 실시간은 신호만, 실패는 한 줄), 폴더 `제안`, 데이터, 테스트
- `DESIGN.md`: 원칙(D-008, NFR-006, NFR-007, BR-008), 모바일 기준 표, 화면 틀, 공용/개인 화면, 토큰 이름(값은 `상경 확정 전`), 컴포넌트 목록, 접근성, 화면 PR 체크
- `CLAUDE.md`: 일 종류별 먼저 읽을 문서 표, 규칙 문서는 담당자가 시킬 때만 고침
- `README.md`, PR 템플릿(보안, 화면 체크), 스크립트 주석 링크
- 개발 프롬프트의 규칙 문서 이름을 고쳐 운영 Hatch 4판으로 저장하고 사본 갱신

## 프롬프트 요약
1. 모두가 따를 규칙 md에 무엇이 필요할지, DESIGN도 필요하다 → 먼저 4개(DESIGN, ARCHITECTURE, SECURITY, CONTRIBUTING), 나중 4개(testing, glossary, decisions, CODEOWNERS) 제안
2. 4개로 진행
3. 각 담당자가 자기 md를 고쳐도 된다. PR이 올라오면 PO가 검사한다

## 사용한 skill
- 없음 (gh CLI로 이슈 #3, 운영 Hatch 문서 저장은 스크립트)

## 확인
- 레포 안 모든 문서 링크 검사 → 깨진 링크 0
- `.github` YAML 문법 → 통과
- `gitleaks dir .` → 비밀 값 없음
- 사본 4개 = 운영 Hatch 최신 판 (dev-prompt 4판)
- 새 사본에서 `claude -p` 로 "S-02 방 만들기 버튼 컴포넌트" → Claude가 CLAUDE, CONTRIBUTING, SECURITY, DESIGN, ARCHITECTURE를 읽고 만듦. 색을 코드에 바로 쓴 곳 0, `md:`/`lg:` 분기 0. 테스트 세션은 영어로 답함 (사용자 언어 설정을 뺀 테스트라서로 보임)
