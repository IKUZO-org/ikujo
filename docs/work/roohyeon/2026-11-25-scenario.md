## 할 일
PRD §28 「생방송 중 사망」을 data §4 형식의 `scenarios/live-death.json` 으로 옮기고, zod 스키마와 검사 함수 `checkScenario()`, 단위 테스트를 만든다.

## 한 일
- `scenarios/live-death.json`: 타임라인, 인물 6, 비밀(인물마다 1개, D-016), 특징 4, 범인 4(동기, 실수, 특징), 단서 22, 레드 헤링 5, 둘만 아는 비밀 6, 라운드 3(8/10/8분, spec §1), 해설(과거 진실, 엔딩 이름)
  - 원문에 없는 문장은 `TODO(시나리오 담당)` 로 비움: 18곳 (아래 남은 일)
  - TODO가 아닌 문장은 전부 PRD 원문 글자 그대로 (단서는 §28.6 실수, §28.7 레드 헤링의 낱말 그대로, 과거 진실은 §28.4 "진실" 줄 그대로). 스크립트로 모든 문장이 `docs/prd.md` 안에 있는지 확인함
- `src/lib/scenario/schema.ts`: zod 스키마. 개인 단서에만 `for`, 핵심이 아닌 인물은 `minPlayers` 필수
- `src/lib/scenario/check.ts`: `checkScenario()` 와 `charactersFor(scenario, n)`
  - 오류: 형식, ID 겹침, 없는 인물/특징/단서/라운드 참조, 범인은 핵심만(BR-003), 레드 헤링 표시와 해설 짝(BR-010), 인물마다 비밀(D-016)
  - `unsupported`: 인원별로 특징 해당 인원이 2명 미만인 범인 (BR-006). 오류가 아니라 목록. OQ-013 임시 결정(spec §9)대로 배정에서 제외할 때 쓴다
- `tests/scenario.test.ts`: 실제 파일 통과, 인원별 등장인물, OQ-013 조합, 오류 케이스 7개
- `package.json`: `zod` 를 dependencies에 추가. 이미 lockfile에 4.6.7(다른 패키지의 하위 의존성)로 있어 버전 그대로, lockfile은 그 두 줄만 바꿈 (로컬 npm 11.7이 lockfile의 `libc` 칸을 지워서 손으로 고침)

검사기가 알려 준 고를 수 없는 범인:
| 인원 | 범인 | 특징 | 해당 인물 |
| --- | --- | --- | --- |
| 4 | 호감 | 시트러스 향수 | 호감 |
| 4 | 선수 | 다리 저는 걸음 | 선수 |
| 4 | 작가 | 무전기 소리 | 작가 |
| 5 | 선수 | 다리 저는 걸음 | 선수 |
| 5 | 작가 | 무전기 소리 | 작가 |

→ 지금 특징으로는 4명 판 범인은 악역뿐, 5명 판은 호감과 악역뿐이다.

## 프롬프트 요약
1. 레포의 파일 규칙을 알려 달라
2. 깃허브 아이디를 알려 줌 → 레포 설정에 저장
3. 내 이슈 목록을 보여 달라 (열린 이슈 없음)
4. 내 담당 단계를 찾아 달라 → 현경이라고 답함 (3, 4, 5, 7, 8단계)
5. develop 최신을 받아 달라 (1, 2단계와 로드맵이 들어옴)
6. 3단계 이슈를 만들어 달라 → #12
7. 브랜치를 만들고 3단계를 시작해 달라
8. 3단계 개발 프롬프트(공통 규칙 + 3단계 지시)를 붙이고 지금 만든 것과 비교해 달라
9. 단서 문장은 원문 그대로 돌리고, docs 규칙 검사(BR-003, BR-010, D-016, 라운드)는 그대로 두라
