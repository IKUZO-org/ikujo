## 할 일
`DESIGN.md` 의 `상경 확정 전` 칸(색, 글자, 간격, 모서리·그림자, 움직임, 다크 모드, 개인 화면 표시, 컴포넌트 모양)을 채우고, 같은 값을 `src/app/globals.css` 의 `@theme` 에 넣는다.

## 한 일
- `DESIGN.md`
  - 이 문서는 UI만 다루고, 그림·영상 규칙은 별도 그래픽 규칙 문서(#23)를 따른다고 나눔
  - 원칙: 화면 대부분은 그래픽, 글은 제목 한 줄 + 한두 줄, 가운데 정렬, 그래픽 위에 글을 겹치지 않음
  - §3 화면 틀: 상단 52px(가운데 단계, 오른쪽 타이머) → 그래픽 영역 → 아래 글과 버튼. 어셋이 없으면 그래픽 영역은 검정 그대로
  - §4 개인 화면: 레드 5px 테두리 + 맨 위 "나만 보기" 띠. 범인에게만 다른 표시 금지
  - §5 토큰: 색(검정, 아이보리, 레드 하나로 UI 통일), 글자 12/14/16/22/30px, 간격 4~32px, 모서리 4/8px, 그림자, 움직임. 대비 값을 표에 적음
  - §5 바뀐 이름: `--text-2xl` 추가(인물 이름, 방 코드). 이전 초안의 `--color-accent` 는 쓰지 않음
  - §6 컴포넌트 9개 모양 + 새 단서 표시, 이름표 칩, 투표 칸
  - §9 그래픽: 그래픽 규칙 문서로 연결, UI 쪽에서 지킬 것만 남김
- `src/app/globals.css`: `@theme` 에 §5 토큰 값, `color-scheme: dark`, `body` 기본 바탕·글자색·글꼴
- 이슈 #23 만듦: 그래픽(이미지·영상) 규칙 문서 추가와 PO에게 `CONTRIBUTING.md` 표 등록 요청

## 프롬프트 요약
1. 레포를 클론해 달라고 함
2. 자신이 디자인(UI) 담당 작업자인지 물음 → 레포 문서에서 상경(UI)으로 확인
3. `ikujo.login` 을 gh 로그인 아이디로 저장해 달라고 함
4. `DESIGN.md` 를 만들어야 한다고 함
5. 팀과 맞춘 아트 디렉션 md(팀 내부 파일)가 PRD, spec 틀에 맞는지, `DESIGN.md` 에 넣어도 되는지 봐 달라고 함
6. 팔레트는 팀과 A안으로 정했다고 알림
7. 그 md는 이미지·어셋 규칙에 가깝다며, UI 토큰을 정해 `DESIGN.md` 하나로 만드는 게 맞는지 물음
8. 무엇부터 해야 하는지 물음 → 이슈 → 빈칸 채우기 → 견본 확인 → PR 순서 안내
9. 이슈가 이미 있는지 물음 → 이슈 #11 만듦, 브랜치를 따서 첫 값을 채움
10. 견본을 띄워 달라고 함
11. 첫 견본이 별로라고 함: 이미지·영상을 크게 쓰고, 글이 많거나 가독성이 떨어지는 방향은 안 됨(팀 합의). UI·버튼 색은 그래픽 팔레트와 달라야 한다고 함
12. develop 을 풀 받아 달라고 함
13. 메인 화면을 포함해 시안으로 만들 화면 목록을 다시 정리해 달라고 함
14. 1~4번(메인, 인물 카드, 라운드, 투표) 시안을 한 장으로 만들어 달라고 함
15. 버튼·UI 색은 그래픽의 레드로 통일, 그래픽 자리는 검정으로 비우고 자리 표시만, 글은 더 작게 가운데 정렬로 고쳐 달라고 함
16. 그래픽(이미지·영상) 전용 문서를 `DESIGN.md` 와 나눌 수 있는지, PRD에 어긋나는지 물음 → 나누는 안으로 진행하기로 함

## 확인
- `npm run typecheck` → 통과
- `npm run lint` → 통과 (문제 0)
- `npm test` → 통과 (3개 파일, 25개 테스트)
- 대비 계산(WCAG 공식, Python): `DESIGN.md` §5 표의 값. 글자 조합은 모두 4.5:1 이상
- `npm run test:db` → 안 돌림 (로컬 Supabase 필요, 이번 변경과 무관)
- 실제 앱 화면(390×844)에서 토큰 적용 확인 → 안 함 (아직 토큰을 쓰는 화면이 없음). 시안은 정적 HTML로만 확인
